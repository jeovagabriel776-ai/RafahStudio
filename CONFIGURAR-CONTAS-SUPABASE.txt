RAFAHSTUDIO — CONTAS ONLINE (VERSÃO CORRIGIDA)

O RafahStudio agora usa o Supabase Authentication como fonte oficial das contas.
O navegador NÃO é o banco de usuários.

1) SUPABASE — BANCO

No Supabase > SQL Editor:
- Execute o arquivo supabase_setup.sql inteiro.
- Se alguma parte antiga já tiver sido executada, pode executar novamente; as tabelas/policies/triggers desta versão usam CREATE OR REPLACE / IF NOT EXISTS quando necessário.

A parte final cria automaticamente um registro em public.rafah_profiles sempre que uma conta nova for criada em auth.users.

2) SUPABASE — AUTENTICAÇÃO

Abra:
Authentication > Providers > Email

Para testar sem confirmação de e-mail:
- deixe Email habilitado;
- DESATIVE "Confirm email".

Com isso:
- o usuário cria a conta;
- recebe uma sessão imediatamente;
- consegue entrar sem esperar e-mail;
- a conta continua salva no Supabase Auth.

Depois que tudo estiver funcionando, você pode reativar a confirmação de e-mail se quiser.

3) COMO O LOGIN FUNCIONA

Cadastro:
Supabase Auth cria o usuário em auth.users.
O trigger cria o perfil correspondente em public.rafah_profiles.

Login:
supabase.auth.signInWithPassword(email, senha)

Ao entrar, o RafahStudio pega o UUID da sessão e carrega o perfil correspondente.

Portanto:
- Chrome → conta A = conta A
- outro navegador → conta A = conta A
- computador diferente → conta A = conta A
- conta B nunca recebe o perfil da conta A.

4) SESSÃO

O site usa uma chave própria de sessão do Supabase:
rafahstudio-auth

Isso permite que o navegador mantenha a sessão autenticada, semelhante ao comportamento normal de sites modernos.
A senha nunca é salva pelo RafahStudio em localStorage.

5) O QUE CONTINUA LOCAL

Nesta versão, pedidos, clientes, orçamentos e alguns caches do workspace ainda são mantidos no navegador, separados pelo UUID da conta.

A autenticação e o perfil do designer são online.

Isso significa que o LOGIN já funciona em outro computador, mas os pedidos antigos ainda não aparecem automaticamente em outro computador.
A próxima etapa, se você quiser, é migrar pedidos/clientes/orçamentos/financeiro para o Supabase também.

6) SEGURANÇA

Nunca coloque a service_role key no app.js ou no GitHub.
Use somente a Publishable Key no frontend.

7) GITHUB PAGES

Depois de substituir os arquivos:
- envie app.js, index.html, style.css, assets/logo.svg e supabase_setup.sql para o GitHub;
- aguarde o GitHub Pages atualizar;
- abra o site em janela anônima;
- crie uma conta de teste;
- abra outro navegador/computador;
- faça login com o mesmo e-mail e senha.

8) TESTE RECOMENDADO

Teste 1:
Criar conta A.

Teste 2:
Sair.

Teste 3:
Criar conta B.

Teste 4:
Entrar novamente na conta A.
O perfil A deve voltar.

Teste 5:
Abrir o site em outro navegador e entrar com A.
O Supabase deve reconhecer a conta A.


NOVA FUNÇÃO — ACOMPANHAMENTO DE PEDIDOS
Execute também a parte final do supabase_setup.sql que cria order_tracking. Depois de atualizar o site, abra um pedido e use 'Acompanhar pedido' para gerar o link privado do cliente. O cliente não precisa de login e vê somente aquele pedido. O painel atualiza o status do link quando o designer move o pedido.
